# 战斗局内 布局交互稿（H1–H4）

入口：[battle.html](./battle.html)。独立 HTML，直接打开即可，无需服务或网络资源。

前篇：二级浮窗稿 [popups.html](./popups.html)（[REVIEW-POPUPS.md](./REVIEW-POPUPS.md)）——战斗页的邮箱/设置浮窗直接复用它的面，本稿不重复出。

## 为什么局内不是「五段骨架」

二级浮窗是操作台（进来看参数、做决定、退出去），五段式成立。局内是**驾驶现场**：画面中央必须留给怪物/弹道/车辆，信息全部贴边压薄，打断层只开一层且一律暂停。所以本稿的组织不是「段」，是**层的打断深度**：

| 层 | 何时出现 | 是否暂停战斗 | 面 |
|----|----------|--------------|----|
| H1 常驻层 | 整局常在 | 否 | 战斗主画面 / BOSS 波次 / 无尽里程碑 |
| H2 打断层 | 升级、手动暂停 | **是** | 升级三选一 / 暂停菜单 |
| H3 浮窗 | 玩家随手开 | 否 | 伤害统计 / 战斗菜单 |
| H4 结算层 | 局终 | 局已结束 | 通关结算 / 失败卡 |

与二级浮窗稿相同的两条硬规矩在这里更严格：

1. **无死键**：局内任何一个可点元素都有出路——技能图标点按弹数值浮窗、暂停三按钮、结算三出路。
2. **一屏读完**：局内零滚动条。伤害统计 4 英雄行以内即收进一屏；礼包/排行这类富列表本就不属于局内（在主城），进了局内没有第二根滚动轴的问题。

## 局内元素清单（全部来自正式项目代码，不是编的）

- **DomHud（DOM 层）**：顶栏（暂停/统计/菜单+邮件红点｜经验条+等级徽章｜波次/击杀 chip）、载具耐久条、低耐久红晕、中央波次提示（第 X 波 / ⚠ BOSS 来袭 / 👑 BOSS 击破）、BOSS 血条、暂停菜单、战斗菜单、伤害统计面板、失败卡、通关卡。
- **AbilityBar（画布层）**：x2 倍速（左列顶部）；1/2 号位靠左、3/4 号位靠右，每英雄 普攻/技能/大招 三槽自上而下；冷却扇形遮罩+秒数；大招击杀充能自底灌满、充满元素亮环；点按弹数值浮窗、长按 0.45s 显示范围圈。
- **LevelUpPanel（三选一）**：撕纸横幅 + 团队升级！选择一项强化 + 三卡错峰滑入；选卡期间整个战斗暂停。
- **结算**：通关卡（击杀/团队等级/金币收益三芯片 + 掉落网格逐项错峰翻转 + 看广告双倍）；失败卡（波次/击杀/等级/金币 + 重试/广告翻倍/返回主城）。
- **模式变体**：普通关卡波次 3/10；无尽波次 chip 变「无尽」+ 里程碑浮动弹幕（不暂停）；试炼失败标题变「试炼失败」；副本结算口径同通关。

## 布局规格（390×844 实测，设计分辨率 1080×1920 换算 ×0.3611）

- **常驻刘海带** 32px 贴顶（桌面也保留，交互稿 `.safe` / 主城 `.safeBand` 同口径）：游戏实现为
  `#domHud { --safeTop: max(32px·--s, --sat) }`，顶栏背景从屏幕顶铺起、内容锚带下，
  bossBar/pauseChip 同步让位；刘海设备 `--sat`（JS 探针填 env(safe-area-inset-top)）撑开带高。
- **顶栏** 44px 贴安全带下沿：按钮 38×34，经验条 flex 占中 + `Lv` 徽章，波次/击杀 chip 定宽 44。
- **技能列**：双列贴边（列中心 x=25 / x=365），图标 Ø33px（设计 92），槽位纵坐标 205/241/277（1、3 号位组）与 335/371/408（2、4 号位组）；x2 倍速在左列顶部 y=165。列在路面之外，不遮车辆与弹道。
- **车尾区** 高 98px（设计 270）：耐久条贴车顶，车辆与上阵英雄头像居中。
- **BOSS 条** 顶部居中宽 250：名字行 + 血量轨道，BOSS 波出现、击破收起。
- **三选一卡** 3 张并排（390 宽下单卡约 112px），内容 = 英雄名 + 强化类型 + 生效说明 + 层数。
- **结算卡** 宽 300：三芯片 + 掉落网格（4 列）+ 双倍广告按钮（文案 = 收益金额）。

## 布局三原则（对齐主城稿的审美纪律）

1. **信息贴边，画面让路**：常驻 HUD 全部贴四边，中央战斗区零遮挡；技能图标宁可小（Ø33）也不进路面。
2. **打断有深度、互斥明确**：H2 一律暂停战斗；升级选卡期间暂停键不响应；浮窗（H3）不暂停、不遮战斗关键区；同屏只开一层。
3. **一屏读完，该滑才滑**：局内没有第二根滚动轴的问题——统计面板 4 英雄行以内收进一屏；内容确实多的面（排行/礼包）留在主城，不进局内。

## 无死键

每个可点元素都有出路（`check-battle.mjs` 逐个 data-act 对分支）：

- 技能图标：点按弹数值浮窗（再点收起），长按显示范围圈（正式项目行为，稿内注明）。
- 暂停菜单：继续 / 重开（清场重置波次，保留倍速与等级）/ 退出（结算已得金币回主城）。
- 通关/失败：广告双倍按钮文案 = 本次收益金额，限次用完或无收益时隐藏（不是置灰）；重试/返回常在。
- 遮罩点击：打断层提示防误触（选卡期间不可关闭），浮窗点遮罩直接关。

node check-battle.mjs   # 31 项断言，失败 0 项

## 落地实施（2026-09-19，除车尾区外全部按稿更换）

游戏侧改动三个文件，`check-ux-refactor.js` 新增 14 项断言锁住口径（248 → 262 项全过）：

- **DomHud.ts ① 顶栏**：高度 88 → 122 设计像素；按钮 62×62 → 105×94（菜单宽按钮 127），
  波次/击杀 chip 改上下两行（标签在上数值在下）+ `box-sizing: border-box`
  （页面没有全局盒模型重置，div 定尺寸不声明会撑出一圈——实测 chip 实渲染 164 而非 122）。
  经验区从「绝对居中 + 徽章叠轨道」改为 `xpWrap` 入流 `flex:1`、徽章在左；
  顶栏菜单按钮必须压制 `.menuBtn` 基类的 `min-width:440`，否则把经验区挤成 0 宽（实测踩坑）。
- **DomHud.ts ② BOSS 条/弹报**：BOSS 条贴顶栏下沿（sat+139）+ 加宽 692 + 名字/血轨放大；
  波次弹报改 `popupMain`+`popupSub` 两行结构，位置 16% → 44%，主行 88 → 62 设计像素，
  副行「本波 N 只」来自 `WAVE_START` 新增第三参（`BattleManager` 发出本波总量）。
- **DomHud.ts H2/H4**：暂停层补顶部状态 chip「时间轴已冻结」与互斥说明；
  `bigLabel` 尺寸改按 `--s` 缩放（旧实现写死 raw px，390 屏上失败标题放大近 3 倍），
  暂停标题 66、失败标题 84 设计像素与通关标题/稿一致；失败标题补副本局变体；
  双倍广告按钮文案改收益金额口径（通关「掉落双倍（+N 金币）」/失败「金币翻倍（+N）」）。
- **LevelUpPanel.ts H2**：标题拆两行（横幅「团 队 升 级」42 + 副题「选择一项强化（点卡即选，无撤销）」），
  顶部补暂停状态 chip，锚**可视区**顶部 `visH/2 - 194` 设计像素——不能写死画布 y，
  横屏裁切视口下写死值会飘出屏外（实测踩坑）；三张卡片整体下移给副题让出间隙。
- **车尾区未动**（载具耐久条/红晕/车体/尾部交互维持原实现），按用户要求排除。
- **验证**：浏览器实测（构建后真实点击）顶栏几何全部命中稿值（122/105×94/127 设计像素）、
  chip 上下行、弹报副行「本波 24 只」、三选一横幅+副题+三卡、升级即暂停恢复、暂停三出路。
  `node tools/check-ux-refactor.js` 262 项、`check-popup-ux.js`、`tc.js`、`check-popups.mjs` 全部 0 失败。
- **环境注记**：页签在后台时浏览器冻结 rAF，Cocos 引擎 spine wasm 初始化会静默卡死
  （表现为主包不发请求、无报错、无场景）——不是代码问题，把页签切到前台即正常；
  构建中途编辑器报 GPU 错误时产物可能不完整，重跑构建即可。
