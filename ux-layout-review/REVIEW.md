# 五大一级页 UX 布局稿 R2

入口：[index.html](./index.html)。独立 HTML，直接打开即可，无需服务或网络资源。

## 本轮确认的三项决定

1. **拖拽穿戴保留。** 这是本稿主动引入、正式项目目前没有的交互，已按要做处理，并在真实浏览器中实测通过。
2. **英雄名与商店页签保持占位。** 稿中"游侠/重炮手/冰霜使/工程师"与"补给/装备/材料/礼包"是设计占位，不按正式项目回填真实名称与页签结构。
3. **天赋归属英雄页。** 天赋入口放在英雄页左侧养成栏，基地不再重复出现。

其余与正式项目不一致的数值（三档宝箱档位、建筑解锁门槛、营地加成百分比等）按同样口径保留为占位值，未做逐项校正。

## 页面结构

- 商店、英雄、护送、行动、基地五个一级页，固定底部五席导航。
- 护送、行动、基地为固定一屏的场景布局；短屏压缩场景空间，不整体缩放页面、不隐藏主操作。
- 角色与六装备槽固定在英雄页上部，六列背包在下部独立滚动，分类与选择摘要固定。
- 英雄页左侧四格养成入口为 技能 / 天赋 / 武器 / 核心；升星与招募、工坊同排。
- 基地只承担建筑、等级与营地增益，8 个建筑两列排布，未解锁项显示门槛。
- 入口以灰阶图标、建筑体块、紧凑标签表达；仅出战、招募等主命令使用面板式按钮。
- 不含二级页面与弹窗。次级入口只显示选择态，选择记录写在桌面评审栏，不占用游戏画面。

## 穿戴演示

- 鼠标：拖动背包装备，放到匹配的装备槽。
- 触屏设计：短划滚动背包；长按约 220ms 后拖动装备。由 Pointer Events 明确区分滚动与拖拽。
- 无拖拽方式：先点选装备，再点匹配槽位。
- 匹配槽位高亮；错误部位不换装；落到槽位外取消。
- 更换时旧装备回到原背包格，背包数量不变，当前英雄战力更新。
- 四个英雄装备分别存储，刷新页面会重置演示。

## 尺寸与滚动

桌面评审栏提供 390×844、360×640、430×932 三个尺寸选项；手机使用实际视窗高度。允许纵向滚动的游戏区域只有背包与商店货架，两者分别按分类保存滚动位置。
