# 五大一级页 UX 布局稿 R2

入口：[index.html](./index.html)。独立 HTML，直接打开即可，无需服务或网络资源。

## 本轮变更

- 商店、英雄、护送、行动、基地五个一级页保持固定底部导航。
- 护送、行动、基地使用固定一屏的场景布局；短屏压缩场景空间，不整体缩小页面。
- 角色及六装备槽固定在英雄页上部，六列背包在下部独立滚动。分类与选择摘要固定。
- 入口用灰阶图标、建筑体块、紧凑标签表达。只保留出战、招募等明确主命令的面板式按钮。
- 删除 R1 的二级页面、弹窗、购买确认与战斗结算。相关入口仅显示选择态；桌面侧栏记录入口选择，不创建二级流程。
- 原型内免费补给和穿戴属于一级页面状态演示，不接正式游戏存档或服务端。

## 穿戴演示

- 鼠标：拖动背包装备，放到匹配的装备槽。
- 触屏设计：短划滚动背包；长按约 220ms 后拖动装备。由 Pointer Events 明确区分滚动与拖拽。
- 无拖拽方式：先点选装备，再点匹配槽位。
- 匹配槽位高亮；错误部位不换装；落到槽位外取消。
- 更换时旧装备回到原背包格，背包数量不变，当前英雄战力更新。
- 四个英雄装备分别存储，刷新页面会重置演示。

## 尺寸与滚动

桌面评审栏提供 390×844、360×640、430×932 三个尺寸选项；手机使用实际视窗高度。尺寸选项表示设计覆盖范围，不代表已全部截图验收。

允许纵向滚动的游戏区域仅背包与商店货架。背包分类、筛选及商店分类分别保存滚动位置。静态页面、英雄装备区与底部导航不参与这些滚动。

## 本次验证记录

运行：

```sh
node ux-layout-review/check.mjs
```

通过 10 项 Node 状态与事件处理测试：

1. 五个一级页面生成，未包含二级页面或弹窗。
2. 穿戴交换保持 66 个装备 ID 完整，背包仍为 42 格占用。
3. 错误槽位不改变背包、装备或战力。
4. 切换英雄后穿戴互相独立。
5. 鼠标拖拽事件路径能正确穿戴。
6. 错误拖拽落点不会误穿戴。
7. 触控短划事件只改变背包滚动位置。
8. 触控长按事件进入拖拽，不同时滚动背包。
9. 指针取消清理拖拽状态与悬浮物品。
10. 背包分类滚动记忆及装备部位筛选正确。

测试使用轻量 DOM 替身验证真实脚本的状态与处理函数，不模拟浏览器排版，也不能证明真实设备的触摸手感。
