# 二级浮窗 UX 布局稿（L2–L5）

入口：[popups.html](./popups.html)。独立 HTML，直接打开即可，无需服务或网络资源。

一级页稿见 [REVIEW.md](./REVIEW.md) 与 [index.html](./index.html)，本轮不重复。

## 为什么是「五段骨架」而不是网页信息流

正式项目的浮窗不是网页卡片，是操作台：进来看一眼参数，做一次决定，退出去。竞品《向僵尸开炮》的五张截图（邮箱两版、装备详情、一键合成、强化台）也是同一个形态——顶部标题或品质头固定，说明/页签固定，中间只有一段可滚，底部消耗与命令固定。

所以本稿抽出的不是样式，是段的顺序与固定/滚动的分工：

| 段 | 承载 | 是否滚动 |
|----|------|----------|
| ① 头部 | 标题，或品质头（4 级灰阶 + 品阶 + 等级） | 固定 |
| ② 说明·页签 | 一句话说明 / 页签 / 筛选条 / 进度条 | 固定 |
| ③ 滚动区 | 列表、格子、对比块 | **唯一滚动轴** |
| ④ 消耗·槽位 | 货币消耗，或材料/装备槽位 | 固定 |
| ⑤ 命令区 | 主命令 + 次命令 + 一行后果说明 | 固定 |

一个面可以缺段（S 档确认框只有 ①③⑤），但**不得有第二根滚动轴**，也不得把 ④⑤ 放进 ③ 里跟着滚走。这是与网页稿最大的区别：网页可以整页滚，游戏不行——用户滚到一半时消耗和「合成」必须还在原位。

## 四档尺寸与五级分层

四档尺寸沿用正式项目 `HomeUiStyle.ts` 的定位口径，不是重新发明的。**宽按档位，高按内容**：

| 档 | 定位 | 高度 | 本稿实测（390×844） |
|----|------|------|---------------------|
| S | `left:50%`、`top:30vh`、定宽 287 | 内容自适应，上限 68% | x52 y253 **287**×260 |
| M | 左右 23、上下 4vh | 内容自适应，上限 92% | x24 **343**×内容（短内容不留空白） |
| L | 左右 17、上下 4vh | 内容自适应，上限 92% | x18 **355**×内容 |
| XL | `inset:0` 满屏二级页 | 满屏 | x1 y1 389×843（手机框 1px 边） |

**高度必须由内容决定**，这是本轮修掉的一个真问题。旧写法把 `top` 与 `bottom` 同时钉死，
在 `height:auto` 下等于「撑满」，于是每一面都被固定成一个高度：邮箱内容 549px 也只得 540px
面板，**差 9px 就白出一条滚动条**；建筑面板内容 638px 同样给 540px，白白多出 165px 空白。
现改为 `height:max-content` + `max-height` 上限，并靠 `margin-top/bottom:auto` 居中（视觉效果
与原固定高度档一致），内容不足时面板收窄到内容高，不再空出滚动条。

配套的一处必须同步改：`.popScroll` 的 `flex:1`（等价 `flex-basis:0`）只在「面板被拉满、
有富余高度」时成立；面板改成内容自适应后它会把滚动区压成 0 高、整块内容看不见，
故改为 `flex:1 1 auto`（以内容高为基准）。

上限取 92vh 而非更高，是实测选的：92vh 能在 844 屏上消掉「礼包」「载具工坊」两条临界滚动条，
而 96vh 一条也多消不掉，只把遮罩留白从 33px 压到 16px（浮层与屏幕边界的区分度变差）。

五级分层：L2 满屏二级页（工坊、钻取底页）、L3 普通弹窗（z220）、L4 半屏抽屉（结算）、L5 结果演出（招募，遮罩更暗且不可误触关闭）。遮罩覆盖整个 844 画框（含信息栏与底导），与正式项目 `.protoMask { inset:0 }` 同口径。

## 无死键

正式项目的按钮不允许出现「点了没反应」。本稿同口径：

- 不出现原生 `disabled`（原生属性会吞掉点击，用户不知道为什么不能点）。不可用一律走 `.off` 压暗 + `data-why`，点下去在提示条里说明原因。
- 消耗行区分足量（`.ok`）与缺量（`.lack`），缺量时按钮压暗并给出差值，例如「强化石不足（缺 7）」。
- 遮罩点击也有出路：L3/L4 关闭，L5/XL 给出「本层需用底部命令关闭，避免误触中断」。
- `check-popups.mjs` 静态证明每个 `data-act` 都有交互分支，且没有孤立分支。

## 竞品参考落到稿里的三条硬规矩

1. **列表行卡**：图标 + 标题 + 标签 + 副标题 + 尾部动作位，未读用右上角标点，不用颜色区分。
2. **品质头**：4 级灰阶 + 品阶标签，不依赖颜色也能读出品质。
3. **对比块**：强化/升级给出「当前 → 强化后」两值，与强化台截图一致。

### 本轮修正的六处缺陷

1. **提示条被重绘清掉**：`claim`/`cta` 先调 `feedback()` 再 `render()`，而 `render()` 整块重写 `.phone`，提示节点被替换，文案丢失（按钮点了没反馈）。改为文案存变量、由 `feedbackHTML()` 回填。
2. **提示条压住命令区**：原来贴屏幕下沿，正好盖住 ⑤ 命令区。改回正式项目 `.toastEl` 的屏幕中央口径。
3. **消耗行露出字面量 `"/>`**：`costRow` 内部又包了一层 `art()`，把已构建的 `<svg>` 片段当图标名。统一为「片段型组件收 art 片段，`cell` 收图标名」。
4. **返回键飘到面板中央**：`popBack()` 直接挂在 `.pop` 上，`position:absolute; top:50%` 以整块面板为参照，落在 y431 压住正文。移入有定位的头部块，现落在 y100（头部 25–205 内）。
5. **宝箱行折行被压**：进度宝箱行原用 `.popFixBar`（`flex-wrap:wrap`）+ 内容宽度浮动，折成两行后下沿被命令区压住。抽出 `chestRow()` 固定 4 列，任务页与结算页共用。
6. **六个面缺 ①头部**：邮箱、公告、任务、签到、一键合成、四档尺寸原先直接从 ② 或 ③ 开始，连关闭键一起没有，用户只能盲点遮罩退出。已补 `banner()`/`topbar()`。

### 一、补齐 22 处死键

### 二、出口补全

- **`.popQ` 缺 `position: relative`**（真 bug）。✕ 是 `position:absolute; top:50%`，
  品质头没有定位时会以整块 `.pop` 为参照，落到面板垂直中心压住正文——就是本稿在
  草案里踩过的同一个坑。修前 ✕ 落在 y≈430（面板中心），修后落在 y=188（品质头 160–246 内）。
- **L5 结果层遮罩点击静默**。引擎默认「L5/XL 不点关」，但没给出任何说明，点了没反应等于死键。
  现改为统一提示「本层需用底部命令关闭，避免误触中断」。
- 两处 L5 结果演出层（招募结果 / 礼包结果）显式设了 `maskClose: true`，**保留不动**。
  一度按本稿「L5 不点外部关闭」的口径去掉了，但项目里已有一条断言要求它们可点关，
  且理由更硬：奖励在弹层出现前就已入账，演出只是回顾，允许快速收起比强迫看完动画更省摩擦。
  引擎默认值服务「不该被误触跳过的层级」，这两个层不属于此列，属正当例外，已回退并在两处补注释。
- XL 满屏页的遮罩实测点不到（`.pop` 铺满整屏，`.protoMask` 无内边距），
  不需要额外出口，但上面的提示分支仍是兜底。

### 三、面板高度由内容决定（二级浮窗尽量不出滚动条）

旧写法 `top`+`bottom` 同时钉死，`height:auto` 被当成撑满，于是**每一面高度固定**，
短内容也硬占满一屏高、中间白白多出一条滚动条。改成 `height:max-content` + `max-height` 上限 +
`margin:auto` 居中后，浮层（M/L/S）滚动条 **8/10 → 2/10**：

| 面板 | 改前 需要/可给 | 改后 | 结果 |
|------|---------------|------|------|
| 邮箱 | 401/391 | 401/401 | 消除（改前只差 10px） |
| 任务 | 487/311 | 487/487 | 消除 |
| 礼包 | 673/410 | 630/630 | 消除 |
| 指挥中心 | 472/274 | 472/472 | 消除 |
| 载具工坊 | 472/258 | 472/472 | 消除 |
| 图鉴 | 521/486 | 521/521 | 消除 |
| 招募 | 727/310 | 727/547 | 仍滚（内容 727px 超上限） |
| 排行 | 980/486 | 980/647 | 仍滚（内容 980px 超上限） |

剩下的「招募 / 排行」是内容真的装不下（727px、980px），属于该滚的情况，不是缺陷。
XL 满屏页保持满屏不做自适应：它们本来就是二级页，滚动条来自内容确实超过一屏（试炼 1211px）。

配套把 `.popScroll` 的 `flex:1` 改为 `flex:1 1 auto`——面板一旦按内容定高，`flex-basis:0`
会把滚动区压成 0 高，整块内容反而看不见。交互稿 `popups.html` 同步改了同一处。

### 说明

`check-popup-ux.js` 里「禁用按钮全部带解释出口」这条是按**花括号配平**解析每个
`disabled:` 所在的对象字面量，再要求同一对象内有 `onDisabled`/`onBlocked`，
而不是靠正则数距离——后者加几行就会漏判。

两份检查脚本里原先写死了 `flex:1` 简写来断言「滚动区是唯一滚动轴」，本轮改基准后
双双误报。已改成断言真正的契约（`.popScroll` 是唯一 `overflow-y:auto` 的弹层区，
命令区/消耗区 `flex:none`），不再绑定某个 flex 简写写法。

图标与美术仍是占位（emoji/SVG），美术样式与资源按约定留给下一轮。
