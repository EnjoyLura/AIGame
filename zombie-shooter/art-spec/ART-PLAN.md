# 游戏美术资源阶段计划（ART-PLAN）

> 2026-09-20 v2。方法论（用户定调）：**先按游戏 UI 归纳出所需 UI 组件清单 → 按 UI 分类分批
> 生成同类美术资源**（按钮类/图标类/面板类……），一族一张 2K 绿幕表一次成型。
> `game_art_benchmark2.png` 本身就是这份清单的布局示范，其中「框/徽」类件可直接取用。

## 0. 总纲

- **方法**：组件清单 → 按类分批 → 2K 绿幕大表一次成型（15~25 格）→ gpt-image-2 edit 模式
  锚定基准图2 → prompt 只报槽位名、不指定形状颜色 → `slice_sheet.py` 切片落盘 → 换图不换 key。
- **风格锚**：`game_art_benchmark2.png` 为唯一基准（casual 基准图仅作面板/按钮参考）。
- **放弃策略（冻结不清盘）**：现有在库图降级为「临时版」继续服役，各批次成套整族替换；
  缺图自动回退占位兜底，游戏全程可玩。
- **每批收尾**：目检过 §6 验收清单 → 切片落盘 → MANIFEST 登记 → 构建 → check 链 →
  新端口烟测 → 提交推送（一族一个 commit，可整体回退）。

## 4. 共性纪律（每批强制）

1. 一类一表一次成型；prompt 只报槽位名；绿幕底 + 间隙；2K 起步。
2. 出图先与基准图2并排过验收清单（STYLE-SPEC §6），再切片。
3. 换图不换 key；新 key 先登记 AssetLib MANIFEST（文件可后到）。
4. 同族 emoji 一并替换收口，不让 emoji 与贴图长期混排。
5. 一批一个 commit：素材 + meta + 接线 + 规范更新同包，可整体回退。

## 5. 风险与决策点

| 风险/决策 | 处理 |
|---|---|
| 基准图2 直取件的分辨率上限 | 只直取显示位 ≤128px 的框徽件；按钮/面板/小图标一律重生成 |
| 基准图2 非绿幕底 | 批0 用 edit 模式重绘背景为纯绿（组件保持不变） |
| 怪物走帧风格混源 | 保留走帧（动作资产），单图重生成拉近 |
| 人物整表一致性 | 2×2 大格 + 2K；四张并排比对再切 |
| 九宫格面板契约 | 四角 24px 等宽，量测后配 9-slice；不达标重出 |
| 长条件（绶带/横幅/按钮板）变形 | P0 `--rect` 落地后自然比例切片 |
